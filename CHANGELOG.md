# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

Version 0.1.0, the first version. It is not published to the Marketplace; install it from a VSIX built from source.

### Added

- Chat view in the Secondary Side Bar, also available in an editor tab, with a status bar entry and the commands New Conversation, Focus Chat, Open Chat in Editor Area, Add Selection to Chat, Check Claude Code Again, Sign In to Claude Code, Show Logs and Delete Stored File Contents and Change History for This Folder.
- Detection of the locally installed Claude Code CLI (2.1.295 or newer, native `claude.exe` on Windows), its version and sign-in state, with a status indicator and banners. Sign-in opens a terminal running `claude auth login` with the detected executable. A notice appears when `ANTHROPIC_API_KEY` is set. Credentials are never read, stored or forwarded.
- Conversations that persist across restarts, with history, search, rename and delete, a model selector (Claude Code aliases plus custom ids), and context attachments: files and folders by `@` mention, the editor selection and the current problems.
- Ask mode: read-only questions with exactly four tools (Read, Grep, Glob, AskUserQuestion), a guard that verifies what Claude Code reports at the start and on every tool call, prompts for reads outside the workspace, optional web tools, a notice for plugins and hooks (or a refused turn with `agentCanopy.readOnly.strict`), and a check after each turn that reports workspace changes.
- Plan mode: persistent plans saved through a plan tool, with immutable versions, decisions and open questions, each version a card in the chat that opens the plan as a read-only Markdown document, compare with the version before in the diff editor, revert to a version, a plan lock, and approval and execution through a native confirmation.
- Agent mode: edits inside the workspace applied and tracked, with prompts for commands (unless Auto is on or the command is read-only), protected paths, anything outside the workspace, web access and external tools; always-allow rules limited to literal commands; tool cards that show who allowed each call; optional sandbox (`agentCanopy.agent.sandbox`); a warning for unsaved files.
- Auto for Agent mode: a per-conversation switch with which terminal commands and edits inside the folder run without a prompt for each one, and web fetch and search too unless `agentCanopy.agent.auto.webTools` is off. It is off for every new conversation, branch and side question and is turned on only through a native dialog, which can also be used before the first message of a new conversation; turning it off needs no dialog and takes effect at once, also during a turn. Protected files, anything outside the folder, other tools and MCP tools, and commands while `agentCanopy.agent.alwaysAskCommands` is on or that ask to leave the sandbox still ask. Shown on the switch, on messages ("Agent · Auto"), in History, on the plan card and in the plan approval dialog, and as "Auto-approved" on tool cards. With the sandbox configured, a turn with Auto cannot leave it. This removes a safeguard on purpose: commands run unreviewed with your privileges, and review and checkpoints do not undo what they do outside the folder. The settings `agentCanopy.agent.auto.enabled` (default on) and `agentCanopy.agent.auto.webTools` (default on) control it.
- Saved permissions per workspace folder, and a Permissions tab. **Always allow** on a permission card is now also offered for a folder to read from (reads and searches in it and below), for a web site to fetch from (the exact host) and for a plain PowerShell command, each confirmed in a native dialog. Three switches, off by default and turned on only through a native dialog, let reads outside the folder, web fetch and web search run without asking. The tab lists everything saved for the folder, including Bash commands and MCP tools saved before, with Remove, which applies to the next request, also during a turn; **Allow reads in a folder...** saves a folder from the system's folder picker. Protected files and other tools still ask, and so do edits outside the folder unless you saved the folder for edits (next entry). Everything is stored in the extension's workspace storage, never in the repository or in VS Code settings. Open the tab with **AgentCanopy: Show Permissions** or **More actions > Permissions**.
- Edits outside the workspace folder can be allowed for a folder. In Agent mode the card "Edit a file outside the workspace" offers **Always allow** for the folder that holds the file, and the Permissions tab has **Allow edits in a folder...**. After a native dialog, which names the folder and the workspace folder, edits in that folder and below no longer ask, for this workspace folder only; reads and searches there stop asking too, in every mode. Review and checkpoints do not cover files outside the workspace folder, and the dialog says so. The tab lists these under "Folders (read and edit)", next to "Folders (read)", with **Remove**. Protected files (`.git`, `.vscode`, `.claude`, `.husky`, `.devcontainer`, `.github/workflows`, `.env` files, `.npmrc`, `.netrc`, `.mcp.json`, `.gitattributes`), credential locations, AgentCanopy's own storage, network shares and a link that points out of the folder still ask. A folder saved for reads only and the reads switch never allow edits, and Auto does not cover edits outside the folder by itself.
- Read-only terminal commands run without asking in Agent mode (Bash only), labelled "Allowed by AgentCanopy", like in Claude Code. A command passes when it is made only of listed commands (`ls`, `cat`, `grep`, `rg`, `find`, `sed` with print-only scripts, `git status`, `git diff`, `git log` and others, with listed options), joined with `|`, `&&`, `||` or `;`, has no variable, substitution, `~` path, glob or redirection other than `2>&1`, `>&2` and `/dev/null`, and names only files inside the workspace folder after links are followed. It is judged for each call; a saved rule and Auto are checked first and keep their labels; `agentCanopy.agent.alwaysAskCommands` turns it off. It needs the working directory that Claude Code reports to the hook AgentCanopy installs in Agent mode, so commands of a subagent, and every command with `disableAllHooks` in your Claude Code settings, still ask. PowerShell commands are unchanged. Every Bash call of an Agent turn now starts in the workspace folder, so a `cd` does not carry over to the next call. See the Agent mode guide and SECURITY.md.
- Reads and searches of Claude Code's memory for the workspace folder (`projects/<slug>/memory` under `~/.claude` or `CLAUDE_CONFIG_DIR`) no longer ask, in Ask, Plan and Agent mode. Edits there, the memory of other projects and the rest of `~/.claude` still ask.
- Review of agent changes independent of Git staging: a Changes card under the chat, native diff editor, CodeLens, gutter marks and a status bar entry, with accept and reject per change, file or all. Keys: Alt+] and Alt+[ to move between changes, Alt+Enter to accept and Alt+Backspace to reject the change at the cursor. Changes that may hold your own work always ask before they are rejected, are kept out of Reject All unless ticked (or entirely, when both you and the agent changed the file or it was reconstructed after an interruption), and files that cannot be restored are marked.
- Detection of configuration changes made by an agent turn (Claude Code and editor settings, hooks, skills, `.mcp.json`, Git hooks), which must be kept or reverted before the next Agent turn, and a note when the agent changed Git state.
- Crash recovery for interrupted turns, with a cross-window lock per folder and "Recover now".
- Checkpoints: a history of agent turns, rejects and restores per workspace folder, a restore preview that sorts files into will be restored, needs your decision and cannot be restored, restores that can be undone, and retention settings that never remove what a pending review entry or the last Agent turn needs.
- Conversation branches from any message, exact where Claude Code allows it and rebuilt from visible messages otherwise, each labeled with which it got and what a rebuilt one lost, with its own copy of the plan and a notice when files are newer than the branch. Restore and Branch From Here combines a restore with a branch.
- Settings under `agentCanopy.*` for the provider path, default mode and model, web tools, strict read-only mode, edit approval, command approval, sandbox, forks, unsaved files, snapshot limits and exclusions and checkpoint retention. Every setting but `unsavedFiles` has machine scope, including the default mode and model.
- No telemetry and no network requests of its own. A loopback-only server serves the CLI's permission, plan and tool-hook calls, protected by a per-turn token.
- Keyboard support for the tabs (Chat, Checkpoints, History, Permissions) and review actions, theme colors only with extra borders in high-contrast themes, and status announcements for screen readers. Checked with automated tests, not yet with a screen reader.
- Mermaid diagrams in chat messages with the classic layout; the ELK layout engine is not shipped.
- A notice when an always-allow rule could not be saved.
- Pasted images: paste a PNG, JPEG, GIF or WebP image into the message box (at most 5 images and 5 MB together per message) and it is sent with your message through Claude Code's `--input-format stream-json` input. Image content is kept in memory only, never stored; the history keeps the image's type and size. Text-only messages are sent exactly as before.
- `npm run package` writes the license text of every bundled package to `dist/THIRD_PARTY_LICENSES.txt`, which ships in the VSIX with the third-party notices and the security policy.
- Changes card under the chat: configuration changes with the path opening the diff and Keep and Revert, always visible while there are any, and changed files with Accept All, Reject All (files of uncertain source only when ticked), Open All in Diff Editor, Accept and Reject for each file, the path opening the diff, and an Accepted group. While an Agent turn runs in the folder it says that file changes can be reviewed when the turn ends, in place of the file list. It can be collapsed; the configuration section stays visible, and while configuration changes are undecided an Agent message cannot be sent and Approve and Execute is disabled, with a hint that says where to decide. Review of single changes is only in the editor: CodeLens, gutter marks and the keys.
- Plan mode in the chat: a plan request card, a plan options card (the agent asks its choices with a question before it writes the plan), and one plan card per version. The current card opens the plan, lists your decisions and what is still to decide, and offers Approve and Execute, View changes and Revert to the version before; an older card opens, compares and restores its own version. The title opens the plan as a read-only Markdown document, the exact text that is approved; VS Code's own Open Preview shows it rendered. The execution message reads "Plan approved: executing version N".
- Stop and Send are both shown while the agent works. The mode can be changed while the agent works; the choice applies to the next message, not to the running turn. An Agent or Plan message sent meanwhile is queued, one per conversation, in a chip above the message box with Edit, Remove and Send now. It is sent when the turn completes. After a stop or an error a message of any mode stays and the chip offers Send. A queued Agent message is held back, with Send disabled and a line saying why, while configuration changes are undecided or another Agent turn runs in the folder, and is not sent by itself afterwards: press Send. A queued Plan message is not held back. Send now stops the turn and sends it, unless a queued Agent message could not be sent afterwards for one of those reasons; a warning says why. A queued message is kept in memory only.
- Side question: a message sent in Ask mode while the agent works (choose Ask during the turn) is answered alongside, in a Side question card in the chat, with its own Stop and Open as conversation. It knows the conversation up to the last finished turn, not the work in progress, and the agent never sees it. One runs at a time per conversation, and while the agent works Send in Ask mode waits until it has finished or been stopped. It is a branch, listed in History under its conversation as a side question.
- Model versions in the model selector: "Sonnet 5.5", "Opus 5.5", "Haiku 5.5", "Fable 5.2" and "Default (Claude Code decides)". The versions come from a table built into the extension and are corrected by what Claude Code reports: when a turn that used an alias or `default` completes, the full model id it reported is remembered, per machine in the extension's global storage, and its version is shown from then on. A turn that fails or is stopped teaches nothing, ids in `agentCanopy.customModels` are shown as typed, and hovering over the selector shows the full id. AgentCanopy does not query the provider for models, so a label can be out of date until a turn has run with that alias on this machine.
- Orchestrate and delegate for Agent mode: an entry of the model selector, "Fable 5.2 · orchestrate and delegate" (stored as `fable+delegate`). `<model>+delegate` in `agentCanopy.customModels` adds the option for another model, and `agentCanopy.defaultModel` may be such a choice. In Agent mode, also when an approved plan runs, the turn runs on the named model and AgentCanopy adds an instruction that tells it to keep the planning, decisions and final review, and to hand searches and reading to subagents on Haiku and routine implementation and tests to subagents on Sonnet, running only readers in parallel. It is an instruction to the model, not an enforcement. A subagent's commands, edits, reads and web calls reach AgentCanopy's policy and are tracked, reviewed and undone like the model's own, but without Auto a subagent's read-only commands ask, a permission card does not say which subagent asked, and changes that parallel subagents make at the same time may not be attributable to one tool call. The plan approval dialog says when the conversation uses such a model. In Ask and Plan mode and in side questions the choice runs as the plain model, and a build older than 0.1.7 fails on a stored `+delegate` choice. See the Agent mode guide.
- Documentation: README, guides for each mode, review and checkpoints, troubleshooting, limitations, security policy, architecture, contributing and publishing notes, and third-party notices.

### Security

- A check of the project's own Claude Code configuration (`.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json`) before every turn in every mode. When it can run programs or change the environment, a native dialog offers Ignore Project Settings or Use Project Settings. The answer is remembered until the files change. Ignoring skips the project's settings, its `CLAUDE.md` and its tool servers. The command Ask Again About This Folder's Claude Code Project Settings clears it.
- Every shell command, file read and search, edit and web access reaches AgentCanopy's policy. In Agent mode a command asks unless you chose Always allow for that exact command, turned on Auto for the conversation, or it is read-only (see below). Reads inside the workspace pass and reads outside ask, in every mode, unless you allowed them for the folder or they are reads of Claude Code's memory for the folder.
- A read or search whose path AgentCanopy cannot be sure to read the way Claude Code will now asks, instead of being judged as inside the workspace: a path with whitespace or a control character at either end and, on Windows, a path rooted without a drive, a drive letter without a separator, a segment that ends in a dot or a space, and a glob pattern written with backslashes, whose folder part is now judged where it points.
- Saved permissions are decided by the extension host at every request, not by Claude Code. A permission is added, or a switch turned on, only through a native dialog; the chat view can only take them away. Credential locations under the home folder, AgentCanopy's own storage and, on Windows, network paths always ask, whatever is saved. The one exception is Claude Code's memory for the folder, which can be read without asking. A folder saved for edits is added the same way and lets edits outside the workspace folder run without asking, with protected files and the locations above still asking; a drive root, the home folder, a folder that holds it and a folder inside the workspace folder cannot be saved for edits.
- The read-only check for commands is a fixed allowlist of commands and options, not a list of forbidden ones, because GNU tools and git accept abbreviated long options. Anything not understood asks. It refuses a folder that is or holds a credential location, a `PATH` with a relative or in-folder entry, project settings in use that hold environment variables, hooks or helper commands, and, for git, a folder without its own `.git` directory at its root or with git environment variables set. It trusts the user's and the system's git configuration and the shell profile, as Claude Code does, and a command you approved that runs at the same time can change files between the check and the run. See SECURITY.md.
- `.gitattributes` is a protected file: edits to it ask, also with Auto on, because it selects diff and filter drivers that git's system configuration defines (`astextplain` and `git-lfs` on Git for Windows).
- Permission cards show every line of a command, mark each line break and long runs of blank lines, give the line count and warn about multi-line commands. Always allow is not offered for a command that starts with an environment variable, and the warning about commands that run project code covers more commands.
- Links in Mermaid diagrams are inert. Invisible direction-changing and zero-width characters in code blocks are shown as markers with a warning, and Copy copies the original.
- Log redaction covers tokens, e-mail addresses and the home folder in many spellings.
- The Claude Code executable is found only through absolute paths and probed from the home folder. The sign-in fallback terminal opens in the home folder.
- Native confirmations also guard deleting a conversation. Text from the model or the workspace is shown in dialogs on one line with control characters written out.

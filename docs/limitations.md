# Limitations

This page lists what AgentCanopy does not do, does not guarantee, or cannot undo. It is meant to be complete. If you find a limit that is missing, please report it.

## Read-only modes (Ask and Plan)

- **The guarantee covers the agent's own tools, hooks, skills and other tool servers.** It does not cover hooks from Claude Code's managed policy, helper commands that Claude Code runs when it reads its settings, or plugins. Ask and Plan turn off hooks from your own settings, but an administrator's hooks cannot be turned off. When a plugin other than the built-in ones is loaded, the turn shows a notice that the guarantee is downgraded, or stops with `agentCanopy.readOnly.strict` on. A hook that runs shows a notice, or stops the turn with the strict setting on.
- **Reads inside the workspace folder are not prompted.** That includes files such as `.env`. Claude Code sends what the agent reads to the model.
- **The check after a turn compares file metadata, not content.** It reports changes and never reverts them. It does not see ignored files (`.gitignore`, `node_modules`, `.git` and similar), and it is skipped for a folder with more than 500,000 files.
- **Web tools, when you turn them on, send queries and page addresses off your machine.** Each use asks first, unless you turned on a web switch or saved a site for the folder (see [Saved permissions and switches](#saved-permissions-and-switches)).
- The guarantee depends on Claude Code honoring the options AgentCanopy passes. AgentCanopy verifies what Claude Code reports, but it cannot look inside Claude Code.

## Agent mode

- **A command you allow runs with your privileges and can do anything you can**, unless `agentCanopy.agent.sandbox` is on. The sandbox exists on macOS, Linux and WSL2 only, and still leaves the workspace folder and temporary directories writable. AgentCanopy requests the sandbox through settings and cannot verify that it is active.
- **Auto removes the prompt for commands on purpose.** With Auto on for a conversation, terminal commands run without asking (unless `agentCanopy.agent.alwaysAskCommands` is on), with your privileges, and text in files, tool output or web pages can steer the agent. The protections for protected files and for paths outside the folder apply to the file tools, not to commands. Review and checkpoints undo file changes inside the folder only, not what a command does outside it, to Git, to databases or over the network. With Auto on, web fetch and web search also run without asking by default (`agentCanopy.agent.auto.webTools`); turning that off and keeping web tools behind a prompt still does not stop data leaving, because commands have network access. [SECURITY.md](../SECURITY.md#auto) lists the limits in full.
- **Turning `agentCanopy.agent.auto.enabled` off clears Auto only while AgentCanopy is running in some window.** The extension starts only when its view is opened or one of its commands runs. The setting turns Auto off in every conversation on this machine, also in workspaces that are closed at the time, and turning it back on arms none of them. A setting switched off and on again while AgentCanopy is not running anywhere (no window open, or no AgentCanopy view opened yet in the open ones, or the settings file edited by hand) is not noticed, and the conversations that had Auto keep it. If AgentCanopy cannot save the reset (a warning says so), a workspace opened before it is saved still has its conversations' Auto; the save is retried when settings change and when the window closes.
- **Some tools never reach AgentCanopy's policy**, with or without Auto: subagent launch, tool search, scheduling and messaging tools and the others that Claude Code runs without asking. Their cards say "Allowed by Claude Code". The calls that a subagent makes itself do reach the policy: its commands, edits, reads and web calls are judged like the model's own (see [Orchestrate and delegate](guide/agent-mode.md#orchestrate-and-delegate)).
- **Rules in your own Claude Code settings can still pre-approve some tool calls** other than commands, reads and web access, which always reach AgentCanopy's policy. Such calls show as "Allowed by Claude Code". `agentCanopy.agent.alwaysAskCommands` also ignores your saved always-allow rules, so every command asks, and it stops Auto from approving commands. It turns off read-only commands too: they ask as well.
- **Ignoring a project's Claude Code settings also skips the project's `CLAUDE.md`**, together with its settings files and tool servers. The agent then does not see the project's instructions until you choose **Use Project Settings**. AgentCanopy cannot split the two.
- **Always-allow rules exist only for plain literal commands**, not for patterns. A command that contains quotes, pipes, redirections, substitutions or globs, or that starts with an environment variable, asks every time, unless Auto is on or the command is read-only (see below). A PowerShell command can be saved only as a plain literal command: letters, digits, spaces and `_ . / \ : -`, up to 300 characters, matched by its exact text. Any other PowerShell command, with a quote, a pipe, a semicolon, `$` or any other character, asks every time, unless Auto is on.
- **Read-only commands are a fixed allowlist, judged for each call, and they can read any file inside the folder.** A Bash command made only of listed commands and options, whose files all lie inside the folder, runs without asking ([Agent mode](guide/agent-mode.md#read-only-commands)). It can read any file in the folder, `.env` files included, as the Read tool can, and what it prints is sent to the model. Anything not understood asks.
- **Read-only commands trust the configuration you and your system already have, as Claude Code does.** That is git's user and system configuration (its pager, `core.fsmonitor`, and the diff and filter drivers that configuration defines, which a repository's own `.gitattributes` may select; edits to `.gitattributes` therefore ask) and the `PATH`, aliases and functions of your shell profile. git may also update its own index when it runs `git status`. [SECURITY.md](../SECURITY.md#read-only-commands) has the details.
- **A command you approved, running at the same time, can change files between the check of a read-only command and its run.** For example, it can replace a file inside the folder with a link that leads outside. The check follows links when it judges a command, and cannot hold the files still afterwards.
- **Read-only commands need the PreToolUse hook that AgentCanopy installs.** AgentCanopy takes the working directory from it and learns from it that a call is not a subagent's. With `disableAllHooks` in your Claude Code user settings, and for every command a subagent runs, commands ask as they did before. Project settings you chose to use that hold environment variables, hooks or helper commands switch read-only commands off too.
- **On Windows, MSYS paths such as `/c/...` ask, and so do git commands in a folder whose `.git` is a file** (a linked worktree or a submodule). PowerShell commands are not judged and still ask unless saved or Auto is on.
- **"Orchestrate and delegate" is an instruction to the model, not an enforcement.** The model decides what to delegate, and AgentCanopy does not check that it did. In Ask and Plan mode and in side questions the choice runs as the plain model, because those modes have no subagent tool. Subagents run on Haiku and Sonnet whatever the orchestrating model is, and each starts with only its brief, so a small task can cost more delegated than done directly.
- **A subagent's text is not shown.** The chat shows the launch card of the subagent with its own tool calls nested inside it, and what the orchestrating model says about the result.
- **A permission card does not say which subagent asked.**
- **Without Auto, a subagent's read-only commands ask.** The read-only check passes only calls of the main session, so without Auto a turn with a delegate model asks more often than a plain one. With Auto it does not.
- **Parallel subagents that change files at the same time may not be attributable.** AgentCanopy may not be able to tie each change to one tool call. Such changes are listed as changed while the agent was working ("mixed" or "unattributed" in the review), and Reject All leaves them alone. The instruction asks the model to run subagents that edit files or run commands one at a time; it cannot prevent the other case.
- **Background tasks are disabled.** The agent cannot keep a dev server or a watcher running between turns.
- The agent has text search (Grep and Glob) but no symbol search.
- You can attach at most 50 files, folders, selections, problem lists or images to one message.

## Saved permissions and switches

These apply to the switches and saved folders, sites and PowerShell commands of the [Permissions](guide/agent-mode.md#permissions) tab, and to **Always allow** on a card.

- **The list of credential locations is a backstop for the common ones, not a list of everything that is private.** Reads and searches outside the folder always ask, whatever switch or saved folder, for these: under your home folder `.ssh`, `.aws`, `.azure`, `.gnupg`, `.kube`, `.docker`, `.config`, `.claude`, `.claude.json`, `.npmrc`, `.netrc`, `.git-credentials` and `.pypirc`; on Windows the `AppData` folder, and on macOS the `Library` folder; AgentCanopy's own storage folders; and on Windows a network path that starts with two backslashes. Case is ignored on Windows and macOS. Nothing else is on the list. The one exception is Claude Code's memory for the workspace folder, `projects/<slug>/memory` under `.claude` (or under `CLAUDE_CONFIG_DIR`, when that is an absolute path): reads and searches there do not ask, in every mode. Edits there, other projects' memory, a link in the memory folder that leads elsewhere, a memory folder that is itself a link and a folder whose slug is longer than 200 characters still ask. Folders whose paths give the same slug (every character other than a letter or digit becomes `-`) share one memory folder in Claude Code itself, so each can read the other's. With the reads switch on, files such as a `.env` file in another project or, on macOS and Linux, your shell's history file are read without asking, and so is anything in a saved folder; what is read is sent to the model.
- **A saved site or the web fetch switch lets file contents leave in an address.** An address can carry text in its path or query, and the agent can put what it read there. With the web fetch switch on this holds for every address, and with a saved site for every address on that site. A fetched page can also carry instructions for the agent.
- **A saved site matches the exact host only.** The match is on the host in lower case, and on the port when it is not the default one for `http` or `https`. `docs.example.com` does not cover `example.com`, `a.docs.example.com` or `docs.example.com:8443`. The scheme is not part of the site, so `http` and `https` on the same host both match. An address with a user name or password, one that is not `http` or `https`, and one with a backslash, a space or a control character cannot be saved and is never matched by a saved site. Only the web fetch switch lets it through without asking.
- **A redirect to another site is reported to the agent, not followed.** Its next request is judged on its own: it asks unless that site is saved or the switch is on. This is taken from Claude Code's documentation and was not tested in a run.
- **Permissions belong to one workspace folder and to one workspace storage.** Another project asks again, and so does another folder of a window with several folders. Nothing is stored in the repository or in VS Code settings, so nothing comes with a clone.
- **Some path forms always ask, because AgentCanopy cannot be sure to read them as Claude Code will.** Such a path or pattern is treated as outside the folder and asks with only **Allow once** and **Deny**; no switch or saved folder covers it, and a path inside the folder written this way asks too, also with nothing saved. These are a path with whitespace or a control character at either end, and on Windows a path rooted without a drive (`/c/Users/...`, `\Users\...`), a drive letter without a separator (`C:Users`) and a segment that ends in a dot or a space (`.ssh.`). For a pattern the last rule looks only at the part before its first wildcard. How Claude Code itself treats such paths was not tested in a run.
- **With the reads switch on, and also inside a saved folder, these still ask:** a search that starts at your home folder or above it, because it would reach the credential locations; network paths on Windows (`\\server\share`); a pattern with `..` after a wildcard or with an alternative in braces that starts at a root, a drive or your home folder (`{a,/etc/*}`); and on Windows the temp folder, because it lies under `AppData`.
- **A glob pattern is judged by the part before its first wildcard.** A `..` after the first wildcard (`src/*/../../x`) and brace expansion that leads to another place (`{src,../other}/*`) are not analysed for whether the pattern stays inside the folder, so a pattern whose first part is inside the folder is treated as inside and does not ask. They are only analysed to keep such a pattern from being covered by a switch or a saved folder when it starts outside.
- **A search is judged by where it starts.** Links below the starting point are not checked, so a link inside a saved folder that points elsewhere is followed or not as the search tool decides. A direct read of a path through such a link is judged by where the link leads, and asks when that is outside the saved folder.
- **Edits in a folder saved for edits are not reviewed and cannot be undone by AgentCanopy.** Review and checkpoints cover the workspace folder only. A folder saved for edits (in Agent mode, from **Always allow** on the card of an edit outside the workspace folder or from **Allow edits in a folder...**) lets the agent edit there without asking, and also read and search there, in every mode. Protected files, credential locations, AgentCanopy's own storage, network shares on Windows and a link inside the folder that points out of it still ask, with only **Allow once** and **Deny**. A folder saved for reads only and the reads switch never allow edits, and Auto does not cover edits outside the folder by itself.
- **A repository's own git configuration can make a git command run a program, although the card labels it as one that only looks** (such as `git status`, `git diff` or `git log`), without the warning about project code. This holds for Bash and PowerShell commands alike. A read-only git command that runs without asking trusts git's own user and system configuration in the same way (see above).

## Pasted images

- **Images can only be pasted** (Ctrl+V or Cmd+V) into the message box: PNG, JPEG, GIF or WebP, at most 5 images and 5 MB together per message. A clipboard that also holds text, as Excel, Word and browsers often do, pastes the text and no image.
- **A message with an image still needs text.** Image-only messages are not supported.
- **Queued messages together hold at most 20 MB of pasted images.** Beyond that a message with images is not queued, and a warning says: "Too many images are waiting in queued messages. Send or remove a queued message first."
- **AgentCanopy does not store image content.** The bytes stay in memory until the message is sent and the turn ends. Your conversation history keeps only the image's type and size, so earlier messages show an image chip without a preview, and a new window or a restart cannot resend them.
- **Claude Code keeps the image in its own session.** Later turns and exact branches still see it. When Claude Code no longer has the session, or a branch is rebuilt, the earlier images are gone: the new session only learns that an image was attached, and AgentCanopy says so.
- **Branching at your own message keeps its text, not its images.** Paste them again in the branch.
- Checked against Claude Code 2.1.323 on Windows. Images use Claude Code's `--input-format stream-json` input; text-only messages are sent exactly as before.

## Change tracking and restore

- **Only the workspace folder is tracked.** The tracked set leaves out VCS directories, `node_modules`, `.venv`, `venv`, `__pycache__`, files ignored by Git, and paths in `agentCanopy.snapshots.exclude`. Symlinks are recorded and never followed. Empty directories are not tracked. A rename shows as a delete plus a create. A folder with more than 500,000 files is only partly tracked, and AgentCanopy shows a note about it.
- **Changes a command makes to ignored, oversized or over-budget files are detected but not restorable.** Their earlier content was never captured. See `agentCanopy.snapshots.maxFileSizeMB` and `agentCanopy.snapshots.maxTotalSizeMB`. Files the agent edits with its own file tools are always captured before the edit, up to 256 MB.
- **Files matching sensitive patterns** (`.env` files, key and certificate files, `.npmrc`, `.netrc`, `credentials` files, anything in `.ssh` or `.aws`) are hashed and not stored, except that the content before an edit by a file tool is kept, with owner-only permissions. The result of such an edit cannot be restored.
- **File restore does not undo Git operations, databases, network calls or anything outside the workspace folder.** If the agent changes Git state, a note says so.
- **Directories left behind.** Rejecting a created file removes the file, not the directories that were created for it.
- **A hand edit made outside the editor that a command overwrites in the same turn cannot be recovered.** If you change a file with another program while a turn is running, and a command of the agent overwrites that change in the same turn, your version was never captured and is gone.
- **A change someone else makes in the fraction of a second after a command ends can be attributed to that command.** The tracker closes a command's window when its result arrives, and an edit of yours or another program's in that gap looks like the command's work.
- **Files over 256 MB are never written** by a restore. They are left as they are.
- **Hard links and extended attributes are not preserved.** A restore writes a new file and renames it into place.
- **A sub-millisecond window** remains between the last check of a file and the rename that replaces it. A change made by another program inside that window is not detected beforehand. AgentCanopy checks again after writing and keeps a copy if the file changed.
- **Line-by-line review** works for UTF-8 text files up to 2 MiB. Other files are accepted or rejected whole, and binary files have no diff.
- **Moving a workspace folder starts with empty AgentCanopy storage.** Conversations, plans and history of the old location stay where they were.
- **One window per folder.** Only one VS Code window can track changes in a folder at a time.
- **Unsaved editor content is invisible to the agent.** It reads from disk. AgentCanopy warns, but does not save for you.

## Forking and checkpoints

- **Exact forks from an earlier message depend on a Claude Code flag, `--resume-session-at`, that is not in Claude Code's CLI reference.** AgentCanopy checks that the installed CLI accepts it, uses it only when the turn it cuts at finished normally, and `agentCanopy.forks.exactEarlierMessages` turns the feature off. It may stop working in a future release.
- **A rebuilt branch carries only the visible text.** It is rebuilt from the visible messages within a size budget. It does not carry tool inputs and outputs, the model's reasoning, files and selections attached to messages, or pasted images, and the oldest messages are dropped if the transcript is too long. The branch header names what was not carried over.
- **A branch is not exact until its first turn has run, and an exact branch can become rebuilt** if Claude Code no longer has its session.
- **Deleting a conversation deletes AgentCanopy's copy, not Claude Code's own transcript.** Claude Code keeps its sessions on its own schedule and removes old ones after its own retention period. A conversation whose session was removed continues with its visible messages as context.
- **Checkpoints are kept for 50 steps and 30 days by default.** Older ones cannot be restored. Anything a pending or accepted review entry still needs, and anything after the last Agent turn, is kept regardless of these settings.
- **A restore only writes files whose content was captured.** Files in the "Cannot be restored" group of a preview (unsaved in the editor, content not kept, blocked path) are left as they are.
- **Restore and Branch From Here branches only when every chosen file was restored.**
- Forking never changes files, so a branch can see a folder that is newer than the point it was forked from. The branch says so when later turns changed files.
- You cannot fork from the last message of a turn that is still running.

## Sending while the agent works

- **Nothing can be added to a running turn.** Claude Code reads its prompt once, when the turn starts, and AgentCanopy knows no documented way to steer a turn that has begun. A message sent while the agent works is queued (Agent and Plan) or answered apart (Ask).
- **One queued message per conversation.** A second one is refused until you edit, remove or send the first.
- **A queued message is lost if the window reloads** before it is sent. It is kept in memory only, never stored.
- **A queued Agent message is not sent by itself once a blocker clears.** Configuration changes that are undecided, or an Agent turn of another conversation in the folder, hold it back; press Send afterwards. Send now does not stop the turn in that case, and a warning says why.
- **Send now stops the running turn first**, with the limits of Stop, including that on Windows the Claude Code session keeps nothing of the stopped turn (see Platform below).
- **A side question does not see the turn in progress.** It knows the conversation up to the last finished turn, with the context rebuilt from the visible messages, so it has the limits of a rebuilt branch (see above). It has its own copy of the plan, read-only, and what is decided there does not reach the original conversation's plan. The agent never sees the question or its answer.
- **One side question at a time per conversation**, and none inside a side question that you opened as a conversation. Each one is a branch stored as a conversation, a copy of the finished turns, until you delete it.

## Platform

- **Tested on macOS.** Windows and Linux are covered by the CI configuration, which has not been run yet. Expect problems there.
- **On Windows, 8.3 short names are not recognised as protected paths.** A short name such as `.GIT~1` for `.git` is not matched by the protected-path list, so an edit through it does not get the extra prompt.
- **Windows supports the native install only** (`claude.exe`), not npm shims.
- **Stopping a turn on Windows is a hard stop.** On macOS and Linux AgentCanopy interrupts Claude Code first, and the partial answer is kept. On Windows the process and its children are killed, so the Claude Code session keeps nothing of the stopped turn. That includes a stop made by **Send now** on a queued message: the message is sent into a session that does not contain the stopped turn.
- **On Windows, the process of an interrupted turn cannot be matched by its start time**, so after a crash AgentCanopy may ask you to stop the old process yourself and choose **Recover now**.
- Virtual workspaces and folders that are not on the local file system are not supported. In an untrusted workspace nothing runs and only history is readable.

## Interface

- **A compromised webview could still start a turn or allow a single command without a native dialog, and with Auto it could do more.** In a conversation where you turned Auto on, a compromised view can start Agent turns, or queue messages, whose commands and in-folder edits run without any prompt, with your privileges; it cannot turn Auto on. Native dialogs guard the high-impact actions, and the Content Security Policy and the HTML sanitizer exist to keep script out of the view in the first place. [SECURITY.md](../SECURITY.md) lists what a compromised view could still do.
- **Plans are cards in the chat and a read-only Markdown document, nothing more.** The document is the source: a plan's diagrams are shown as Mermaid text, not drawn, and there is no stage dependency diagram. File names in a plan are not links. A plan version compares only with the version before it, and a plan cannot be exported. In a branch (also a side question opened as a conversation, and Restore and Branch From Here), the turns copied from the original conversation show the plan execution message with its stored text "Execute plan version N" instead of "Plan approved: executing version N", and they do not carry the plan options cards, because branches never carry prompts; the answers are still listed on the plan card under "Your decisions". Review of single changes (hunks) is only in the editor, through CodeLens, gutter marks and the keys, not in the Changes card.
- **Mermaid diagrams in chat messages use the classic layout only.** The ELK layout engine is not shipped with AgentCanopy because of its license (EPL-2.0). A diagram that explicitly asks for the ELK layout cannot be drawn and shows its source instead.
- Links in Mermaid diagrams are inert: their text stays and nothing opens.
- Diagrams are drawn only when their code block is complete, at Mermaid's strict security level, and with labels as plain SVG text rather than HTML.
- Accessibility has been checked with automated tests only. It has not been tested with a screen reader. See the README.

## Provider (Claude Code)

- **Claude Code is the only provider**, and it must be installed locally at version 2.1.295 or newer. AgentCanopy does not include it.
- **AgentCanopy was built against observed behavior of Claude Code**, recorded on macOS with version 2.1.322 (see `docs/protocol/claude-cli.md`). Windows and Linux, authentication failure and rate-limit output, the shape of subagent events and very large writes were not observed. A new Claude Code version may change behavior that AgentCanopy relies on.
- **The model list is not queried from the provider.** It is Claude Code's aliases plus the ids you add in `agentCanopy.customModels`, because Claude Code cannot list models. The version in the label of an alias comes from a table built into the extension and is corrected by what a completed turn reported: when a turn that used an alias or `default` completes, the full model id is remembered per machine, for all windows and projects. A label can be out of date until a turn has run with that alias on this machine, for example after Claude Code points an alias at a newer model, and a turn that fails or is stopped teaches nothing. An id that does not have the shape `claude-<family>-<major>[-<minor>]` (for example a cloud provider's id) keeps the built-in label for an alias; the tooltip still shows the reported id.
- **A build older than 0.1.7 does not know the `+delegate` form of a model choice.** A conversation that stored such a choice fails there with "model name contains characters that are not allowed" until another model is picked.
- **Context usage is approximate.**
- **Usage is yours.** Every turn uses your Claude Code subscription limits or API billing. Check Anthropic's current terms for Claude Code and your plan.
